# Codex 额度唤醒器 PRD

## 1. 产品目标

让 Windows 用户通过一个单页工具设置不受日期跨度限制的一次性有限序列和额外单次唤醒。电脑处于睡眠状态时，系统按时唤醒、保持清醒并完成一条真实的本地 Codex 请求，以便用户验证五小时用量窗口是否被触发。

## 2. 目标用户

- 使用 ChatGPT 账号登录 Codex 的 Windows 用户。
- 不希望编写 PowerShell、手动维护 Windows 计划任务或排查多层调度日志的非技术用户。

## 3. 核心流程

1. 用户打开程序，填写序列首次日期/时间、间隔和序列执行次数；次数可以是 0。
   用户也可以点击首次日期/时间旁的“现在”，将首次时间设置为当前本地时间的下一个整分钟。
2. 用户点击“测试触发”，确认 Codex CLI、登录状态、模型和网络均可用。
3. 用户点击“保存并启用”，程序创建一个 Windows 计划任务。
4. 到点后 Windows 唤醒电脑并启动程序的后台模式。
5. 程序保持电脑清醒，等待网络，执行 `codex exec`，记录响应与退出码。
6. 用户下次打开程序即可看到最近执行结果；若启用了自动睡眠且能确认本次计划唤醒、请求成功、唤醒后无人操作，程序在 60 秒可取消倒计时后请求普通睡眠，否则交还系统原电源策略。

## 4. 第一版功能

### 必须实现

- 统一的一次性有限序列：设置不受日期上限约束的未来首次执行日期与时间、间隔和次数；默认间隔为 5 小时 10 分钟，之后按该间隔执行。
- 首次日期/时间提供“现在”快捷按钮：只更新当前未保存的输入值为下一个整分钟，不自动保存、启用或执行。
- 序列执行次数包含首次执行，可为 0；0 次不生成序列，仅执行额外唤醒，1 次只执行首次时间。
- 可插入任意未来日期时间的单次唤醒；每条插入唤醒同样执行 Codex 触发，并与其他触发合并到同一条 Windows 计划任务。
- 模型选择，默认 `gpt-5.6-luna`。
- 可编辑的短提示词，默认只要求回复固定成功文本。
- 测试触发。
- 保存并启用、暂停、删除计划任务。
- 唤醒运行、错过时间后尽快运行、避免重复实例。
- 后台请求和重试期间由程序自动保持清醒，使用内部有限执行预算，不再提供保持清醒时长输入。
- 网络等待与最多 3 次 Codex 请求重试。
- 最近一次状态、时间、退出码、输出摘要和日志入口。
- 自动发现 Codex CLI；找不到时给出可执行的解决建议。
- 可选的“任务唤醒电脑后，成功完成时自动睡眠”，默认关闭；严格校验唤醒来源并检测用户操作。

### 暂不实现

- 不操作或复用 Codex 桌面 App 自带的计划任务。
- 不保存 ChatGPT 密码、Token、Cookie 或 API Key。
- 不自动判断额度窗口是否真的重置；第一版通过成功响应和 Usage Dashboard 人工复核。
- 不支持 Windows 关机后的 BIOS/RTC 开机，只支持系统允许的睡眠或休眠唤醒。

## 5. 界面与交互

- 单窗口，顶部使用独立的“当前启用计划”摘要，显示 Windows 计划任务是否存在、是否实际启用、是否允许唤醒、下次与最后一次触发时间。
- 摘要下方用可滚动的时间线展示当前计划序列：每一条的日期时间、来源（序列第几次或插入唤醒）和相对状态（已到期、下一次、待执行）。
- 主内容区域在高度不足时提供右侧垂直滚动，不允许底部区域被压缩到不可读。
- “当前执行序列”和“最近一次结果”使用可拖动的水平分隔线；用户可按需要拖动，优先把空间分配给正在查看的区域。
- 摘要所用的“已启用/已暂停”必须从 Windows 计划任务读取；配置文件只作为计划内容的来源。
- “保存并启用”须明确写为更新同一条 `CodexQuotaWaker-Schedule`，不会创建重复计划；已存在任务时按钮文案应反映“更新”。
- 中部显示统一计划的首次日期、首次时间、间隔和“序列执行次数（含首次，可为 0）”。
- 首次日期和首次时间旁提供“现在”快捷按钮；点击后把两项设置为当前本地时间的下一个整分钟，并立即刷新计划摘要与时间线，但不自动保存或执行。
- 序列执行次数为 0 时首次日期、时间和间隔置灰；用户通过“插入额外唤醒”添加单次计划。
- 序列执行次数为 0 时“现在”按钮随首次日期和时间一同禁用。
- 有限序列的首次执行时间只要求晚于当前时间，不限制必须是今天，也不设置未来天数上限。
- 界面必须明确提示“总次数包含首次执行”，并展示由此得到的最后一次计划时间。
- 底部提供“测试触发”“保存并启用”“暂停”“删除计划”“打开日志”。
- 模型与重试设置下方提供自动睡眠勾选框；计划状态和最近结果显示启用状态、唤醒证据及跳过原因。
- 默认只展示用户需要理解的信息；技术错误放入日志，同时在界面给出下一步。
- 高风险或不可恢复操作仅限“删除计划”，且只删除本程序统一命名的计划任务。

## 6. 约束与边界

- 使用当前 Windows 登录用户的 Codex 登录状态。
- 用户必须保持 Windows 会话已登录；锁屏和睡眠允许，注销不保证执行。
- 电脑固件和当前电源方案必须允许唤醒计时器。
- `CC Switch` 或其他本地代理属于 Codex CLI 的上游配置；程序记录其错误但不修改代理配置。
- 后台请求使用只读沙盒，避免为了触发窗口而修改文件。

## 7. 验收标准

1. 程序能在全新目录双击启动，不要求安装额外运行时。
2. 能创建包含 `WakeToRun=true` 的 Windows 计划任务。
3. 测试触发成功时能获得非空模型回复和退出码 `0`。
4. 错误模型、无网络或未登录时，界面与日志能指出具体原因。
5. 配置保存后重新打开程序仍可恢复。
6. 构建和验证脚本可重复执行，且不会改动用户现有 Codex 定时任务。
7. 有限序列示例：首次时间为 `2026-09-06 02:15`、间隔为 `5 小时 10 分钟`、总次数为 `3` 时，触发时间依次为 `02:15`、`07:25`、`12:35`，第三次后停止。
8. 当用户序列次数为 `0` 并额外插入 `2026-09-07 09:00` 时，只写入这一条单次触发；与序列重合的额外时间自动去重。
9. 自动睡眠关闭、手动测试、请求失败、唤醒来源不明或唤醒后检测到用户操作时，不发送睡眠请求；测试验证不使真实电脑睡眠。

## 8. 视觉风格

- 原生 Windows、浅色、克制、无装饰性动画。
- 状态颜色只表达成功、运行中、警告和失败。
- 中文界面；命令、模型名和日志字段保留英文。
- 表单遵循两行分组输入：日期/时间、间隔、次数不在窄窗口中强行挤成一行。
