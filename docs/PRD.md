# Codex 额度唤醒器 PRD

当前版本：`0.17.0`

## 1. 产品目标

让 Windows 用户通过一个单页工具设置不受日期跨度限制的一次性有限序列和额外单次唤醒。电脑处于睡眠状态时，系统按时唤醒、保持清醒并完成一条真实的本地 Codex 请求，以便用户确认当前请求链路是否联通以及最终由哪个模型响应。

## 2. 目标用户

- 使用 ChatGPT 账号登录 Codex 的 Windows 用户。
- 不希望编写 PowerShell、手动维护 Windows 计划任务或排查多层调度日志的非技术用户。

## 3. 核心流程

1. 用户打开程序，填写序列首次日期/时间、间隔和序列执行次数；次数可以是 0。
   用户也可以点击首次日期/时间旁的“现在”，将首次时间设置为当前本地时间的下一个整分钟。
2. 用户可选择“重启或注销后仍运行”；该选项默认关闭，普通睡眠唤醒不需要开启。
3. 用户点击“测试请求链路”并确认后，程序并行刷新本机 Codex CLI 可用模型目录和沿当前配置发起的一次真实请求；目录结果只更新下拉候选，不改当前选择或本次请求快照。程序展示链路状态和本次最终响应模型；若响应提供可靠的官方额度重置时间，则把尚未保存的首次时间调整到重置后的下一整分钟。
4. 用户点击“保存并启用”；若选择未登录运行，程序通过 Windows 原生凭据窗口收集当前帐户密码，并交给任务计划程序加密保管。
5. 到点后 Windows 唤醒电脑并启动程序的后台模式。
6. 程序保持电脑清醒，等待网络，执行 `codex exec --json`，记录响应、退出码、实际链路和最终模型；手动测试若取得唯一且可靠的带时区重置时间，则只预填未保存的序列首次时间。
7. 用户下次打开程序即可看到最近执行结果；若启用了自动睡眠且能确认本次计划唤醒、请求成功且唤醒后无人操作，程序在 60 秒可取消倒计时后请求普通睡眠，否则交还系统原电源策略。

## 4. 第一版功能

### 必须实现

- 统一的一次性有限序列：设置不受日期上限约束的未来首次执行日期与时间、间隔和次数；默认间隔为 5 小时 10 分钟，之后按该间隔执行。
- 首次日期/时间提供“现在”快捷按钮：只更新当前未保存的输入值为下一个整分钟，不自动保存、启用或执行。
- 可选的“重启或注销后仍运行”：默认关闭；普通睡眠唤醒不需要开启。开启后界面必须明确说明需要当前 Windows 帐户密码、开机 PIN/指纹/人脸不可用，并使用 Windows 原生凭据窗口注册任务；本程序不保存密码。
- 后台计划注册失败时必须解包并识别 Windows 返回的底层错误，至少区分密码/PIN错误、批处理登录权限不足、访问被拒绝和未知错误；提示原因、下一步和“原计划未修改”，日志只记录脱敏后的异常类型与错误码。
- 计划状态必须显示实际任务的登录要求；关闭该选项时明确提示更新重启后可能漏跑。
- 序列执行次数包含首次执行，可为 0；0 次不生成序列，仅执行额外唤醒，1 次只执行首次时间。
- 可插入任意未来日期时间的单次唤醒；每条插入唤醒同样执行 Codex 触发，并与其他触发合并到同一条 Windows 计划任务。
- 请求模型默认 `gpt-6-luna`，保留自由输入；连接测试确认后调用本机 `codex debug models` 刷新目录，仅将 `visibility=list` 且 `supported_in_api=true` 的模型作为下拉候选，维持 CLI 顺序并按 slug 去重。目录刷新不额外发送模型请求；失败或超时不阻断原连接测试。
- 最近一次有效目录仅缓存模型 slug、显示名称和更新时间到 `%LOCALAPPDATA%\CodexQuotaWaker`；不保存原始 CLI 输出、说明文本或凭据。程序启动只读该缓存，不运行 CLI；缓存缺失、损坏或不可用时回退内置模型列表。
- 刷新候选时保持用户当前模型选择和自由输入值；本次真实请求使用确认前已捕获的模型快照。不得自动选择新模型、保存配置或更新计划。新模型出现或当前选择不在新目录时提供简短提示；目录失败提示“模型列表暂未刷新，仍可测试或手动输入”。
- 空模型回退为 `gpt-6-luna`。旧配置中的内置默认 `gpt-5.6-luna` 只在图形界面打开时迁移为未保存的 `gpt-6-luna` 草稿，并明确提示保存后才更新配置及计划；其他已保存模型值保持不变。
- 主界面常驻展示当前检测到的请求链路、最近一次实际链路和最终模型，不再提供目标模式选择。
- 请求链路测试优先展示“是否联通”和“最终模型”；不再判断官方额度命中或目标完成。
- 每次测试和计划执行都重新检测链路，并从本次 `codex exec --json` 或精确匹配的会话中识别最终模型和非敏感链路信息。
- 手动测试获得带时区的可靠官方额度重置时间时，将序列首次日期/时间更新为换算到 Windows 本地时区后的下一整分钟，并明确提示尚未保存；只有用户点击“保存并启用”才更新 Windows 计划。
- 重置时间只接受本次结构化响应中 `limit_id=codex`、`window_minutes=300` 且唯一的 `primary.resets_at`；Unix 时间戳按 UTC 解释，带显式偏移的 ISO 时间按其偏移解释，冲突或缺少时区时不调整。
- 当 Codex 配置经过本地 CC Switch 路由时，尽力从 CC Switch 日志的“请求目标”行识别本次实际上游和请求模型；能够识别时展示最终模型、DeepSeek/OpenAI 等目标，不可用时显示未确认，不根据模型名猜测。
- 结果区展示最终模型和实际上游，但不评价渠道是否官方，也不建议自动切换路由。
- CC Switch 上游探测只读取日志中的请求 URL、目标 host 和时间，不读取请求头、Token、Cookie 或账号信息。
- 可编辑的短提示词，默认只要求回复固定成功文本。
- 请求链路测试：一次真实请求，展示链路状态和最终模型。
- 手动连接测试只校验请求模型和提示词等请求参数，不校验计划次数、计划日期时间、间隔或额外唤醒；空白/非法次数、过期首次时间和不完整计划不阻断请求。测试确认与请求快照保持不变。
- 计划保存仍执行完整校验。测试不把非法次数静默转换后写入配置或 Windows 计划，也不修改次数/真实计划。只有确认时捕获到有效正整数的序列次数，且现有可靠额度重置规则通过时，才允许预填首次时间；次数空白、非法或为 0 时明确跳过预填并保留草稿。
- 保存并启用、暂停、删除计划任务。
- 唤醒运行、错过时间后尽快运行、避免重复实例。
- 后台请求和重试期间由程序自动保持清醒，使用内部有限执行预算，不再提供保持清醒时长输入。
- 网络等待与最多 3 次 Codex 请求重试。
- 最近一次状态、时间、退出码、实际链路、provider、最终模型和日志入口。
- 自动发现 Codex CLI；找不到时给出可执行的解决建议。
- 可选的“任务唤醒电脑后，成功完成时自动睡眠”，默认关闭；严格校验唤醒来源并检测用户操作。
- 不在命令行、日志、配置、任务 XML、异常信息或项目文件中传递或保存 Windows 密码；取消或注册失败时保留原任务。

### 暂不实现

- 不操作或复用 Codex 桌面 App 自带的计划任务。
- 不保存 ChatGPT 密码、Token、Cookie 或 API Key。
- 不调用 Usage Dashboard 私有接口，不读取额度余额，也不把官方额度信息作为请求成功或目标完成条件；仅可利用本次结构化响应中可靠的重置时间预填未保存的执行计划。
- 不支持 Windows 关机后的 BIOS/RTC 开机，只支持系统允许的睡眠或休眠唤醒。

## 5. 界面与交互

- 主窗口首屏品牌区以原生次要文字显示当前运行程序集的 `vX.Y.Z`，标题栏显示同一版本；后续只更新程序集版本即可自动跟随。与计划版本、文档和配置无关，不新增在线更新入口，不改变请求或计划流程。依据已确认 `REQ-20261008-visible-app-version.md`。

- 2026-10-08 连续执行修复：后台开始前独立恢复可核实的旧记录，GUI 不作为执行历史初始化条件。旧日志必须有独立 scheduled 开始、有效模型响应和成功完成（失败须明确终结）证据；任务定义及配置均需在该次执行前保存且与当前计划一致，每次仅在唯一未关联到期条目时回填。缺失、交错或歧义均不确认。无可靠条目关联的后台运行仍保存独立运行标识及业务结果，不伪造条目成功。

- 时间线按真实执行证据显示执行中、执行成功、执行失败；到期但无可靠关联显示“已到期·结果未确认”，未来保留下一次/待执行。已保存计划拥有独立版本；草稿仅预览，不继承执行结果。后台以当前 Windows 计划定义、版本和启动记录核对唯一未处理到期条目，不按最接近时间猜测；延迟/补跑歧义保留未确认。执行历史保存在 `%LOCALAPPDATA%\CodexQuotaWaker\execution-history.json`，最多 500 条，原子替换并串行保护；仅保存关联、时间、进程身份及业务结果/安全诊断，不保存原始响应或凭据。异常退出不永久显示执行中。历史记录只在计划一致、配置在启动前保存且唯一对应时迁移；无法确认的不迁移。依据 `REQ-20261007-timeline-execution-status.md`，不改变调度、用户任务或最近成功卡片。

- 测试结果使用分层原生 WinForms 弹窗：成功/失败、完成时间、实际响应模型为主信息；模型未确认不影响请求成功。可靠额度预填突出具体首次时间和“尚未保存”，“查看计划”仅导航。技术链路默认折叠并去重，目录反馈独立作为次要信息；长错误/详情可滚动，按钮始终可达。依据已确认 `REQ-20261007-test-result-dialog.md`，本轮只做弹窗，实机视觉尚待验收。

- 单窗口，顶部使用独立的“当前启用计划”摘要，显示 Windows 计划任务是否存在、是否实际启用、是否允许唤醒、下次与最后一次触发时间。
- 顶部“当前启用计划”附近增加“请求链路”状态卡，核心展示链路是否联通、最终模型，并提供最近验证时间、非敏感链路摘要、刷新配置动作和真实测试入口。
- “刷新配置”只读取本地路由信息，不发送模型请求；“测试请求链路”需先由用户确认，然后并行启动一次真实 Codex 请求和最多 10 秒的模型目录刷新。取消确认不启动任一项；目录刷新失败不阻断请求。完成后展示最终模型和 CC Switch 实际上游。
- 模型目录刷新成功时保留当前选择与自定义输入，并提示发现的新选项；若当前选择未出现在新目录中，提示用户可手动调整但不自动切换。本次请求模型快照、最终响应模型证据和可用模型目录始终独立。
- 尚未执行真实测试时，链路卡必须显示“尚未测试”和“最终模型尚未识别”，不能把请求模型伪装成最终模型。
- 摘要下方用可滚动的时间线展示当前计划序列：每一条的日期时间、来源（序列第几次或插入唤醒）和相对状态（已到期、下一次、待执行）。
- 主内容区域在高度不足时提供右侧垂直滚动，不允许底部区域被压缩到不可读。
- “当前执行序列”和“最近一次结果”使用可拖动的水平分隔线；用户可按需要拖动，优先把空间分配给正在查看的区域。
- 摘要所用的“已启用/已暂停”必须从 Windows 计划任务读取；配置文件只作为计划内容的来源。
- “保存并启用”须明确写为更新同一条 `CodexQuotaWaker-Schedule`，不会创建重复计划；已存在任务时按钮文案应反映“更新”。
- 中部显示统一计划的首次日期、首次时间、间隔和“序列执行次数（含首次，可为 0）”。
- 首次日期和首次时间旁提供“现在”快捷按钮；点击后把两项设置为当前本地时间的下一个整分钟，并立即刷新计划摘要与时间线，但不自动保存或执行。
- 首次日期、时间、间隔与“现在”不依赖次数填写顺序，次数空白、暂时无效或为 0 时仍可编辑；预先选择的值在后续填次数时保留。
- 次数为 0 时不生成序列，只执行额外唤醒；次数空白或无效时提示填写非负整数，不虚构序列，保存时明确校验并保留草稿。
- 有限序列的首次执行时间只要求晚于当前时间，不限制必须是今天，也不设置未来天数上限。
- 界面必须明确提示“总次数包含首次执行”，并展示由此得到的最后一次计划时间。
- 请求链路卡提供“测试请求链路”和“刷新配置”；底部提供“保存并启用”“暂停”“删除计划”“打开日志”。
- 模型与重试设置下方提供自动睡眠勾选框；计划状态和最近结果显示启用状态、唤醒证据及跳过原因。
- 默认只展示用户需要理解的信息；技术错误放入日志，同时在界面给出下一步。
- 高风险或不可恢复操作仅限“删除计划”，且只删除本程序统一命名的计划任务。

## 6. 约束与边界

- 使用当前 Windows 登录用户的 Codex 登录状态。
- 用户必须保持 Windows 会话已登录；锁屏和睡眠允许，注销不保证执行。
- 电脑固件和当前电源方案必须允许唤醒计时器。
- `CC Switch` 或其他本地代理属于 Codex CLI 的上游配置；程序只检测和记录其路由状态，不修改配置、账号、Token 或上游渠道。
- 后台请求使用只读沙盒，避免为了触发窗口而修改文件。
- 构建和验证默认使用 `dist/CodexQuotaWaker.exe`；若该 EXE 正在运行，脚本支持显式指定独立临时输出路径完成构建/验证，正式交付路径不变。
- 模型目录缓存只写入本应用 `%LOCALAPPDATA%\CodexQuotaWaker`；仅序列化经校验的 slug、显示名称和刷新时间，不保存 CLI 原始 JSON、凭据或响应正文。

## 7. 验收标准

1. 程序能在全新目录双击启动，不要求安装额外运行时。
2. 能创建包含 `WakeToRun=true` 的 Windows 计划任务。
3. 测试请求链路成功时能获得有效模型回复和退出码 `0`，并显示“链路已联通”。
4. 错误模型、无网络或未登录时，界面与日志能指出具体原因。
5. 配置保存后重新打开程序仍可恢复。
6. 构建和验证脚本可重复执行，且不会改动用户现有 Codex 定时任务。
7. 有限序列示例：首次时间为 `2026-09-06 02:15`、间隔为 `5 小时 10 分钟`、总次数为 `3` 时，触发时间依次为 `02:15`、`07:25`、`12:35`，第三次后停止。
8. 当用户序列次数为 `0` 并额外插入 `2026-09-07 09:00` 时，只写入这一条单次触发；与序列重合的额外时间自动去重。
9. 自动睡眠关闭、手动测试、请求失败、唤醒来源不明或唤醒后检测到用户操作时，不发送睡眠请求；测试验证不使真实电脑睡眠。
10. 当前配置包含本地路由时，请求链路卡可展示简短实际路径，但不要求用户选择目标模式或判断渠道是否官方。
11. 请求成功但最终模型证据不足时，分别显示“链路已联通”和“最终模型未识别”，不得用请求模型替代最终模型。
12. 测试取得可靠重置时间 `23:08:42 +08:00` 时，首次执行时间调整为 `23:09` 并提示尚未保存；无可靠时间、时间已过期或序列次数为 0 时，计划输入和已安装任务均不改变。
13. 应用首次打开后，计划编辑入口必须在首屏可见；不能只显示品牌和唤醒摘要。保存与其他操作在其有效父容器内有真实 Bounds，且通过纵向滚动可达。自动验证必须建立真实 WinForms 控件句柄、完成布局后检查关键控件 Bounds 位于可视父容器有效区域，并覆盖双栏/单栏、字体或 DPI 缩放、折叠展开及滚动可达性。
14. 每张卡片的标题和正文占据独立布局区域；句柄建立并完成真实布局后，所有有标题的卡片均须满足标题 Bounds 不与正文 Bounds 或首个正文控件 Bounds 相交。
15. 文字保持原生 WinForms 字体控件显示，不把文字绘制到图片或位图。若用户反馈发虚，检查实际进程 DPI 感知、窗口 DPI、兼容性覆盖和标准控件渲染，并用实际窗口和标题栏对照；没有证据时不得归因于 DPI、ClearType 或颜色对比。
16. 针对文字发软和输入边框观感，诊断实际控件字体、GDI/GDI+ 路径、目标显示器有效 DPI、manifest 与兼容性状态；只有实际窗口对照能证明候选改善后，才调整标准控件的呈现。不得改变 Windows 显示/字体设置，或把正文文字改为自绘/位图。
17. 请求模型默认值和空配置回退均为 `gpt-6-luna`；旧默认 `gpt-5.6-luna` 仅在界面中预填为未保存的 `gpt-6-luna`，保存成功后才持久化。无缓存时保留四个 GPT-6 内置候选；刷新成功后使用本机 CLI 当前公开且 API 可用目录，用户仍可输入自定义 slug。请求模型不得替代实际最终模型证据。
18. 点击“测试请求链路”并确认后，目录刷新与现有真实请求并行；取消确认时不运行目录命令或真实请求，目录命令最多运行 10 秒，失败/超时不能阻断原请求。
19. 只显示目录中 `visibility=list` 且 `supported_in_api=true` 的有效模型，保留 CLI 顺序并按 slug 去重；异常结构、重复项和不公开/不可请求的项安全忽略。目录不能从本次最终响应模型推断。
20. 启动只加载缓存，不运行目录命令；无效/损坏缓存回退内置列表。缓存只含模型 slug、显示名称和更新时间，不含原始输出、说明文本、凭据或响应内容。
21. 成功刷新候选后保留当前已选模型和自定义文本，不自动选择新模型、不保存配置或写入 Windows 计划；本次请求始终使用确认前捕获的请求模型。新选项和当前选择缺失均给出简短反馈。
22. 手动测试时，空白/非法/0 次数、过期首次时间、无效间隔和额外计划状态均不参与请求拦截；仅空模型或空提示词等请求参数错误会拦截。取消确认不发请求。保存并启用仍拒绝无效计划，且不把无效次数保存为 0。
23. 可靠额度重置预填仅使用测试开始前捕获的有效正整数次数；空白、非法和 0 次数即使收到可靠重置证据也不改动计划草稿。有效正次数继续遵循既有唯一、带时区、未来重置时间规则。测试不更新真实计划或写入未完成配置。

## 8. 视觉风格与版式（UI v2）

- 界面按已确认的 `docs/requirements/REQ-20261003-ui-demo-v2.html` 重新组织，不沿用旧式单列表单布局。
- 暖白/浅灰页面底色、白色圆角卡片、细边框、深色文字；紫色作为主要保存操作和当前时间线节点的强调色。
- 页首独立展示大号下次唤醒时间，并清楚区分当前 Windows 已安装计划状态与正在编辑的未保存预览。
- 主内容采用左右分栏：左侧计划编辑、折叠的高级设置与请求链路；右侧可滚动执行时间线、最近结果和独立 Windows 计划状态。窄窗口时自动堆叠为单列。
- 最近结果与计划技术字段默认折叠；用户先看到成功/失败、最终模型、实际链路、实际 Windows 任务是否存在/启用/允许唤醒以及其下次、最后触发时间。
- 计划操作、字段默认值、真实 Codex 请求、脱敏、错误引导与调度语义遵循现有功能约定，不使用 demo 模拟数据。
- 时间线和结果卡片通过可拖动水平分隔线分配高度；主界面支持右侧垂直滚动。
- 日期时间、间隔、次数和单次唤醒在可用宽度内换行；根据 WinForms DPI 自动缩放，不能通过固定像素宽度造成横向溢出或遮挡。
- 版式验证以句柄建立并完成布局后的控件 Bounds 和可视父容器为准；只检查控件实例存在或静态断点常量不足以证明界面可用。默认首屏应露出计划日期/时间编辑入口及保存操作，纵向滚动后所有其他操作均可到达。
- 卡片标题与正文使用独立布局行并验证 Bounds 不相交；文字清晰度按用户实际 100% 显示缩放与约 1440×953 窗口检查，不通过改变 Windows 显示/ClearType 设置规避。
- 输入控件保持 WinForms/Windows 原生交互；边框和焦点样式应简洁、清晰，与卡片表面一致，不使用嵌套的传统 3D 边框。
- 不使用第三方 NuGet 包；保留 .NET Framework 4.8 WinForms 与单文件 EXE。
