# UI-003：测试结果弹窗优化

- 状态：confirmed，用户接受方向后明确要求继续结果弹窗优化。
- 目标/用户：普通用户一眼看懂测试成功与否、最终模型、计划预填是否生效以及下一步。
- 核心：以请求成功/失败为主标题，显示执行时间与最终模型；请求成功但模型证据不足显示“未确认实际响应模型”，不把请求模型替代最终模型、不让用户必须读日志才能理解成功。
- 计划反馈：可靠重置时间仅预填草稿，突出具体首次时间和“尚未保存”；提供“查看计划”按钮，关闭弹窗并定位现有计划编辑区域，不自动保存/注册任务。未预填时简短解释跳过原因，详情按需查看。
- 详情：provider/实际上游/CC Switch 路由合并在默认折叠的技术详情区，已有脱敏信息均可查看，日志入口为辅助选项；不重复堆叠相同上游字段。
- 次要反馈：模型列表刷新/失败信息在次要区域，不改变请求成功状态。
- 失败：明确失败原因与下一步；长错误支持换行/滚动，不撑出屏幕。
- 视觉：沿用已确认现代浅色/紫色风格、标准文本控件；清晰字级与留白，正常正文深色，成功/失败语义色只用于状态。无需竞品或新demo，当前截图和已确认v2设计作为参考。
- 约束：.NET4.8 WinForms、无NuGet、单文件EXE；保留取消确认/请求快照/草稿保护/模型目录刷新/重置预填安全规则。
