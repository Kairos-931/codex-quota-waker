# WAKE-001：离开前检查计划唤醒条件

- 状态：implementation_verified / awaiting_deployment；2026-10-08 用户回复 `0`，批准本版需求与 `gpt-6-luna / max` 开发档位，已交付原开发聊天
- 优先级：P1；来源：用户询问合盖、睡眠与电池状态下能否正常唤醒（2026-10-07），并接受软件内检查与设置指引方向
- 用户目标：设好计划后，直接知道当前电脑在哪种供电/登录条件下可能无法按时运行，以及自己下一步该检查哪里

## 产品行为

1. 在现有主窗口的 Windows 计划状态附近增加紧凑的“唤醒条件”摘要，初次打开与用户点“重新检查”时读取当前 Windows 实况。首屏优先呈现当前供电方式对应的关键问题；展开后分别看插电和电池，不新增一页或常驻后台。
2. 分项展示：当前可用睡眠状态、合盖后插电/电池动作、当前电源方案的插电/电池唤醒定时器、实际安装计划的 `WakeToRun`、任务登录类型/当前会话要求。以正在使用的电源方案和实际 Windows 任务为准，不从保存的草稿推断。
3. 每项仅使用“符合当前设置／需要设置／未能确认”等明确状态。整体文案是“根据当前设置，插电可尝试计划唤醒；电池供电需开启唤醒定时器”等条件描述，不能说“保证唤醒成功”。即使所有设置看似满足，也需标明真正合盖唤醒尚未经实机验证。
4. 对本机已知的“电池唤醒定时器关闭”情形，指出这会影响电池供电睡眠时的定时唤醒，并给出可操作的 Windows 设置路径：电源选项中打开当前方案的高级设置，进入“睡眠 → 允许使用唤醒定时器”，分别检查接通电源与使用电池。提供“打开电源设置”辅助入口时只导航，不自行修改。若当前 Windows 版本未显示该选项，提示按设备/电源模式进一步核对，而非假定已开启。
5. `InteractiveToken` 任务明确说明“锁屏且仍登录”与“注销/重启后未登录”的差别；若已启用后台无登录运行，按实际任务定义显示。不存在计划时提示先保存并启用，不把计划缺失解释为系统唤醒能力失败。
6. 某项读取失败、权限不足、系统不提供该项或结果矛盾时显示“未能确认”及建议的下一步；不能把未知算作通过。当前供电状态、电源方案或任务发生变化，重新检查应刷新，结果带本地检查时间。展示与读取不得调用 Codex 模型。

## 数据与安全边界

- 只读检查 Windows 电源策略与本应用唯一计划任务；不改电源选项、合盖动作、登录方式、任务、用户配置，也不创建临时唤醒任务，不主动睡眠/休眠或发送真实请求。
- 不读取或记录凭据；安全日志只保存非敏感的读取错误诊断。无需持久化检查结论，因为设备和电源方案会变化。
- 当前电源配置满足条件不等于真实唤醒测试成功；实机合盖/睡眠演练另列需求并要求用户参与，不在本项自动执行。
- 保留现有单 EXE、单任务及固定启动入口；不新增外部依赖。

## 可观察验收

1. 插电计时器开启、电池关闭、合盖均睡眠且任务 `WakeToRun=true` 时，插电与电池分别给出不同状态；电池项直说需开启计时器和路径。切换供电/电源方案后重新检查，展示对应新状态。
2. 任务不存在、禁用、`WakeToRun=false`、交互令牌且用户未登录等情况各有准确提示；不把“计划已启用”当成唤醒已验证。
3. 读取失败或不支持相关查询时保留可读取项，问题项标“未能确认”，不显示全绿/保证成功；可重试。
4. 锁屏与注销/重启未登录的解释与实际任务登录模式一致；不要求输入 Windows 密码来做诊断。
5. 窄/宽窗口、100%/150% 缩放下关键问题与设置指引可读、可滚动、不遮挡计划操作；使用原生文本控件。展开技术细节后仍保留核心计划摘要。
6. 诊断与刷新不改变现有任务 XML、配置、结果数据或电源设置；不发真实请求。正式 EXE 与任务引用后台副本更新一致。
