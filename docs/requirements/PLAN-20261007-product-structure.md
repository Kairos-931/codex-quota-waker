# 产品信息结构与功能规划

- 状态：proposal，仅产品方案；不授权开发，不改变当前TIMELINE-001范围。
- 来源：2026-10-07 用户要求考虑信息、结构与功能规划；以下优先级为AI建议，待用户决定。
- 定位：让用户安排可验证的定时Codex请求，并能判断是否具备离开电脑的条件。不承诺请求一定启动/重置额度窗口。

## 信息模型

分别表达：Windows已安装计划、未保存编辑草稿、实际请求执行记录、电源与网络等环境检查。不能把计划到期等同执行，不能把测试成功等同未来合盖唤醒成功，不能把请求模型等同最终模型，不能把上次成功伪装成最新一次尝试结果。

## 单窗口结构

1. 概览（默认）：紧凑计划状态/下一次/剩余次数；最近成功时间与来源、最新失败提示；实际时间线与最近结果保留可拖动分隔；电源或登录阻碍只有需要时突出，详情展开。主操作为编辑计划，辅助为测试连接/暂停。
2. 计划：先时间与次数，再额外时间，右侧/下方草稿预览；未保存状态与保存更新结果明确，主操作可达；模型、提示词、重试、自动睡眠与未登录运行渐进展示；关闭有未保存草稿时明确选择，具体策略需确认。
3. 记录：测试与计划执行共用历史，但按来源过滤；计划时间、实际开始/结束、结果、最终模型及延迟可追查；模型或唤醒证据未知明确标记，不猜测。

不增加侧栏导航、多窗口或装饰统计卡片；宽窗双栏、窄窗单栏，以内容确定高度。三视图是建议，需用户确认后再做可交互demo，现有单窗口/滚动/拖动要求持续适用。

## 功能优先级及对应issue

- 第一阶段，可信状态：当前TIMELINE-001先完成；RESULT-001与STATE-001、UI-001随后单项实施。共用可靠执行记录，分清上次成功与最近失败。
- 第二阶段，信息重排：依据本方案做demo确认；UI-002/003主界面剩余/004/005/006/007按目标合并规划但保持逐项实施验收，避免同一页面反复改造。
- 第三阶段，离开前检查：WAKE-001读取睡眠、AC/DC计时器、合盖、登录条件；无权限标记未知；网络/CLI环境区分当前检查和未来可用性。可选真实合盖演练另列需求并明确用户参与、临时任务和真实请求授权，不能自动执行。
- 第四阶段，恢复与连续使用：基于已确认状态提供失败原因和明确下一步；计划全部完成有完成状态及复用入口；保存草稿与关闭行为需确认；统一历史保留策略。无需自动重复无限执行。

## 暂缓

自动改Windows电源策略、自动切账号/路由、自动升级所选模型、额度余额仪表盘、常驻托盘、手机控制、多账号与复杂图表。当前目标尚无充分证据需要这些能力。

## 成功标准

- 用户首屏能判断计划是否生效、下一次何时、最近成功何时、是否存在需处理的问题。
- 无需日志即可区分测试与计划、成功与失败、配置满足与实机验证。
- 编辑期间能清楚知道哪些尚未生效；保存反馈包含实际去重次数与首末时间。
- 不为查看基本状态支付额外真实请求用量，不改变固定入口或无需常驻的产品边界。
