# REQ-20260922：简化请求链路测试

## 状态

- 阶段：已实现，已完成确定性验证
- 目标版本：`0.11.0`
- 类型：`feat`
- 批准执行配置：`gpt-5.6-luna / max`
- 视觉检查：已批准；已尝试启动构建产物，但当前 Computer Use 未暴露 WinForms 窗口，因此未执行视觉断言

## 目标

让用户只需执行一个“测试请求链路”动作，就能知道两件事：当前 Codex 配置能否完成真实请求，以及该请求最终由哪个模型响应。产品不再要求用户理解或选择“官方 Codex 额度 / 跟随当前配置”两种目标模式。

## 用户流程

1. 用户查看“请求链路”状态卡；未测试时显示“尚未测试”和“最终模型尚未识别”。
2. 用户点击“测试请求链路”。
3. 程序明确提示该操作会沿当前 Codex / CC Switch 配置发送一次真实请求并消耗相应用量，不修改任何路由配置。
4. 成功后优先展示两个核心结果：
   - 链路状态：已联通。
   - 最终模型：从本次真实响应或与本次请求精确匹配的链路证据中识别出的模型。
5. 可在次级信息中展示简短链路摘要，例如 `Codex CLI → CC Switch → 实际上游`；不得抢占两个核心结果的视觉层级。
6. 失败时显示失败环节和下一步，例如 Codex CLI 不存在、未登录、网络/上游不可达、超时或返回内容无效。

## 功能要求

- 删除目标模式选择控件，以及“官方额度命中”“目标完成”等用户可见概念和判断。
- 测试和计划执行始终跟随用户当前 Codex 配置；程序不得自动切换 provider、CC Switch 渠道、账号或模型路由。
- “链路已联通”表示本次真实 `codex exec --json` 请求获得有效模型响应，不代表任何指定额度桶被消耗。
- 最终模型只能来自本次运行的结构化事件或与本次请求精确匹配的本地链路证据；无法可靠识别时显示“未识别”，不得用界面中配置的请求模型冒充最终模型。
- 链路成功但最终模型无法识别时，应分别显示“链路已联通”和“最终模型未识别”，并给出查看日志的入口。
- “刷新配置”可以继续作为不发请求的辅助动作，但只更新当前非敏感链路摘要，不再推导官方/非官方结论。
- 最近一次结果与日志保留必要的退出码、最终模型、provider/上游和失败点；不得记录 Token、Cookie、密码等凭据。
- 计划执行成功以获得有效模型响应为准。自动睡眠不再依赖“官方额度已验证”，但仍必须同时满足原有的计划唤醒证据、无人操作、功能已启用和可取消倒计时等安全条件。
- 兼容旧配置和旧结果中的 `TargetMode`、`OfficialQuotaConfirmed`、`TargetSatisfied`、`QuotaStatus` 等字段：升级后读取不能崩溃，界面和新判定逻辑应忽略这些旧语义；是否保留字段仅作为内部兼容实现决定。

## 不在范围

- 不读取或判断官方 Codex 五小时额度桶、额度余额或重置时间。
- 不新增第二套测试模式、高级目标模式或 provider 切换功能。
- 不修改计划时间、Windows 登录运行策略、重试次数或现有计划任务名称。
- 不以测试为由自动创建、删除或覆盖用户现有计划任务。

## 验收标准

1. 主界面不再出现“目标模式”选择，以及“官方额度命中/未命中”“目标完成”等状态。
2. 用户只需点击一个“测试请求链路”入口，程序即沿当前配置发起真实请求。
3. 有效模型响应返回后，界面明确显示“链路已联通”和本次最终模型；链路摘要为次级信息。
4. 有效响应存在但最终模型证据不足时，链路仍可显示已联通，最终模型必须显示“未识别”，不能回填请求模型。
5. 请求失败时，界面指出失败环节和可执行的下一步，日志保留脱敏诊断信息。
6. 旧版本配置和最近结果可安全加载，不因旧目标/额度字段报错。
7. 自动睡眠以真实请求成功代替官方额度确认作为业务成功条件，其余安全门槛保持不变；自动化测试不得使真实电脑睡眠。
8. 构建、验证和相关自检全部通过，且验证过程不修改用户现有计划任务或真实 Codex 路由。
