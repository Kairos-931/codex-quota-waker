# 最近一次成功联通：统一手动测试与计划唤醒

- 状态：已记录，用户明确提出行为；待当前结果弹窗优化完成后单项细化实施。
- 目标：用户看到最近一次实际成功联通的时间，而非只看到手动测试记录或Windows任务启动时间。
- 入口：主界面截图中的“最近一次结果”卡片。
- 核心：手动测试和后台计划唤醒成功均更新同一份最近成功记录；以真实模型请求成功为依据，时间采用请求完成时间并按本地时区显示。
- 失败保护：新失败不覆盖上次成功时间；最新一次尝试的失败/原因和下一步需独立显示，避免把旧成功伪装为最新尝试成功。
- 呈现方向：“最近一次成功联通”+完成时间+来源（手动测试/计划唤醒）；最终模型、实际链路来自同一次成功证据，不混入其他尝试的字段。无成功记录时显示“尚无成功联通记录”。
- 唤醒概念：计划请求来源只能称为“计划执行”，没有电源唤醒证据时不宣称本次实际唤醒了电脑；Windows最后触发时间继续独立保留。
- 数据：记录位于应用LocalAppData，不存凭据；历史最近执行记录若确认成功可用于初始化最近成功，若仅有失败不能推断更早成功。并发/时间倒序写入不能使较旧成功覆盖较新成功。
- 验收方向：测试成功A→计划成功B显示B；计划成功→测试成功显示测试；成功A→失败B保留A并明确B失败；模型未识别但请求成功仍更新时间；无成功不造时间；成功各字段与来源一致；程序重启后记录保留。
- 约束：保留原EXE与启动入口，不自动改计划或发请求验证；本项不混进当前UI-003结果弹窗开发。
- 执行评估：尚未评估，待单项开发交接时确定。当前仅记录需求。
