## 验收场景

1. 手动成功 A → 计划成功 B，显示 B 的完成时间与“计划执行”；反向顺序显示较新的手动成功。
2. 成功 A → 失败 B，仍显示 A 的成功时间；同卡片独立说明 B 失败、原因和下一步，详情为 B。
3. 有效回复但最终模型未识别，成功时间照常更新，模型为未确认；请求失败、只有任务启动、退出码非零或无有效回复均不更新。
4. 并发和写入顺序颠倒时，最终保留完成时间较新的成功；重启后保留。手动测试不会进入计划执行时间线。
5. 旧版最近尝试为成功时可安全初始化；旧版最近尝试为失败且没有其他逐条可信成功证据时，不伪造历史成功。时间线记录缺字段时不借用别次模型/链路。
6. 无记录、成功、失败和窄窗口／100% 与 150% 缩放下文本可读，无遮挡；原生文字控件。现有计划、额外时间、Windows 任务及固定启动入口不变。
