- 目标：保持有限序列的执行次数不变，同时避开对这份计划没有价值的每日时段

## 行为建议

1. 每份有限序列计划可选择开启一个“每天暂停计时”时段，例如 03:00–05:00；默认关闭。设置保存于这份计划，不是影响所有未来计划的全局偏好。当前计划结束后不继续自动创建或延长；新计划可重新设置。
2. 时段内序列间隔的累计暂停，时段结束后继续累计未完成的分钟数。以当地日历时间每日重复，左边界包含、右边界不包含：03:00 不触发，05:00 可触发。执行次数仍包含首次，不因跳过时段减少次数，也不在 05:00 补发多次。
3. 例：首次 00:00、间隔 5 小时、每日 03:00–05:00 暂停，第二次为 07:00；首次 02:00 时第二次为 09:00。时间线需显示真实预定时间及“间隔计时已跳过 03:00–05:00”的说明。
4. 暂停只影响有限序列。用户明确添加的额外单次时间不受限制，即使落在暂停时段也照常执行，并在界面标出“手动指定”。序列与额外时间碰撞仍只执行一次，来源同时说明。
5. 首次序列时间若落在暂停时段，编辑草稿仍可保留，保存时给出明确提示与最早可用时间建议，不静默修改用户选定时间。执行次数为 0 时该选项没有效果，额外单次时间仍可使用。
6. 保存前以同一计算规则展示全部有限序列预览、去重总次数和最后一次时间；保存成功后 Windows 实际任务触发时间与预览逐项一致。修改暂停时段但尚未保存时只改变草稿预览，当前已安装计划不变；保存失败保留旧计划并解释原因。

## 范围与安全边界

- 第一版建议每份计划支持**一个**每日时段；可跨午夜，例如 23:00–02:00。起止相同（全天暂停）无效，输入错误不能静默保存。
- 保持唯一 Windows 计划任务、同一个 EXE 后台模式、有限序列、额外时间、WakeToRun 和执行历史关联规则。不引入常驻服务，也不以 UI 预览代替实际任务注册。
- 当本地夏令时使某次计划时间不存在或歧义时，不静默改变执行时刻；保存时说明受影响日期/时间并要求调整。旧配置缺少本设置时等同关闭，不改变现有计划时间。
- 平台不能可靠表达某份预览时，阻止保存并保留旧任务；不得截断次数、漏注册后续触发或提前宣称成功。
- Windows 单个任务最多有 48 个触发器。首版可在开启暂停计时后，将去重后的有限序列与额外单次时间显式注册在**同一条任务**中；若总数超出可可靠注册的数量，保存前告知上限与当前数量并保留旧任务，不静默截断。未开启暂停计时时保留现有固定重复触发器，避免给已有计划引入新限制。

## 验收方向

1. 无暂停时段的原有计划行为、次数和任务定义保持不变。
2. 00:00／02:00 开始的上述例子，预览、已保存任务与实际时间线均为 07:00／09:00；多日跨越时每天重复排除 03:00–05:00。
3. 时段跨午夜、起止边界、首次落在时段内、次数为 0、额外单次时间及去重均有明确行为；失败保存不改已安装计划。
4. 一份计划中的暂停设置不默默变成下一份计划的全局规则；计划版本变化后旧执行结果不混入新计划。
5. 宽窄窗口下输入、预览和保存反馈可读；仍使用原生文字控件与固定启动入口。
